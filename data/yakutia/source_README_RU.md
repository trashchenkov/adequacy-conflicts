# Данные пилота: вход для расчёта

Готовы все 19 заданных лет 2005–2023, без отбора лет. Точка 71.7775° N, 139.8471° E; погода PVGIS 5.3/ERA5. Получен один оригинальный ответ за 2005–2022; оригинальный ответ 2023 переиспользован побайтно. Всего 166536 исходных часов. Четыре високосных года сохранены полностью; в отдельном основном наборе удалены ровно 96 часов 29 февраля. Управление и подбор мощностей не рассчитывались.

## Готовые массивы

| Файл | Размер почасовых полей | Назначение |
|---|---:|---|
| `annual_8760.npz` | `(19, 8760)` | Основное сравнение; без 29 февраля |
| `winter_1008.npz` | `(19, 1008)` | 20 ноября 00:00 — 31 декабря 23:00 UTC каждого года |
| `annual_original/year_YYYY.npz` | `(8760,)` или `(8784,)` | Полный исходный календарь одного года |
| `raw/pvgis_era5_2005_2022.json` | 157776 записей | Неизменённый ответ API |
| `raw/pvgis_era5_2023.json` | 8760 записей | Неизменённый архивный ответ |

Порядок строк сводных массивов задан `years = [2005, ..., 2023]`. Все годы включены. `dt_hours = 1.0` — скаляр. `model_hour_index` — общий индекс столбца от 0, размер `(T,)`; он есть только в двух сводных NPZ. В отдельном годовом NPZ вместо `years` есть скаляр `year`.

```python
from pathlib import Path
import numpy as np

base = Path('research_continuation_2026-10-13/online_pilot_2026-10-16/data')
with np.load(base / 'annual_8760.npz', allow_pickle=False) as z:
    years = z['years']
    x = z['x_model_kW']              # (19, 8760), кВт
    x_sensitivity = z['x_typical_winter_scaled_kW']
    month = z['month']              # календарный месяц UTC, (19, 8760)
    hour_local = z['hour_local']    # назначенное UTC+10, (19, 8760)
```

Для зимнего расчёта заменить имя файла на `winter_1008.npz`. При частом почасовом доступе сначала извлечь нужные массивы из NPZ, как в примере: повторное обращение `z[key]` заново распаковывает поле.

## Поля и единицы

Все перечисленные ниже поля имеют форму `(19, T)` в сводных файлах и `(n,)` в исходном году.

| Поле | Тип / единица | Смысл |
|---|---|---|
| `timestamp_utc` | `datetime64[m]`, UTC | Начало часа; часовой пояс задан семантически, NumPy не хранит TZ |
| `pvgis_midpoint_utc` | `datetime64[m]`, UTC | Исходная середина часа PVGIS, без интерполяции |
| `month`, `day`, `hour_utc` | `uint8` | Календарные месяц, день и час UTC |
| `hour_local`, `month_local` | `uint8` | Час и месяц после назначенного сдвига UTC+10 |
| `source_hour_index` | `int32` | Индекс в полном исходном году, с нуля |
| `is_feb29` | `bool` | Маска 29 февраля; в двух сводных файлах всегда False |
| `load_model_kW` | `float64`, кВт | Почти ровная назначенная модель нагрузки |
| `load_typical_winter_scaled_kW` | `float64`, кВт | Повтор 24-часовой зимней модельной формы, пик 1000 кВт |
| `wind_cf`, `pv_cf` | `float64`, кВт/кВт | Доступная мощность на установленный кВт |
| `x_model_kW`, `x_typical_winter_scaled_kW` | `float64`, кВт | Генерация минус соответствующая нагрузка |
| `wind10_m_s`, `wind40_m_s_assigned` | `float64`, м/с | ERA5 на 10 м и назначенный пересчёт на 40 м |
| `temperature_C` | `float64`, °C | ERA5 T2m |
| `pv_reconstruction_flag` | `uint8` | Исходный Int: 1 означает реконструкцию солнечной радиации в PVGIS |

`x = 3000 * wind_cf + 500 * pv_cf - load`. Положительный x означает избыток ВИЭ относительно нагрузки. Собственные нужды H₂ не добавлены; здесь нет мощности внешнего источника, накопителя или управления. Масштабы ВИЭ не подбирались.

Для 2008, 2012, 2016, 2020 в `annual_8760.npz` после 28 февраля 23:00 следует 1 марта 00:00: разность реальных timestamps составляет 25 часов, но соседние столбцы модели разделяет шаг 1 час. Это явное сжатие календаря для сопоставления 365 суток, а не пропуск погоды. Нельзя заново строить временную ось по `model_hour_index`, объявляя её исходной, или умножать энергию такого перехода на 25 часов. Полный календарь доступен в `annual_original/`; удалённые timestamps перечислены в `removed_feb29.json`.

## Источники и ограничения

Методика повторяет [прежний пакет](../../mechanism_study_2026-10-15/winter_sources/DATA_READINESS_RU.md): EWT DW54-500, высота 40 м, `v40 = v10 * 4**(1/7)`, сохранённая оцифрованная кривая, отключение ниже 3 и при 25 м/с; PV c-Si, 60°, юг, 14% потерь. Параметры и единицы подтверждены метаданными ответа и [документацией JRC API](https://joint-research-centre.ec.europa.eu/photovoltaic-geographical-information-system-pvgis/using-pvgis-5/api-non-interactive-service_en). URL, SHA256, параметры API и индексы каждого года внутри исходного ответа находятся в `manifest.json` и `request.json`.

Основная нагрузка равна `1000 * (1 + 0.05 * cos(2*pi*(h_local-18)/24)) / 1.05`, её диапазон 904.76–1000 кВт. Чувствительность повторяет зимнюю модельную форму из локального архива, диапазон 728.15–1000 кВт. Обе формы одинаковы во всех годах и не имеют годовой сезонности; они не являются измеренной нагрузкой Юкагира. В каждом основном году энергия составляет 8342857.14 и 7843278.10 кВт·ч соответственно.

Погода — реанализ; ветровая мощность — собственная реконструкция, PV — расчёт PVGIS. Обледенение, низкотемпературные остановки, фактическая доступность, плотность воздуха и обогрев оборудования не моделируются. Поэтому это погодный вход для условной северной системы, а не проверенный проект объекта. Сдвиг нагрузки UTC+10 сохранён как назначенное допущение прежнего опыта. Первоначальная типовая форма из зимней таблицы используется круглый год только для указанной чувствительности.

Атрибуция: European Commission, Joint Research Centre, PVGIS 5.3; ERA5. [Условия использования PVGIS](https://joint-research-centre.ec.europa.eu/photovoltaic-geographical-information-system-pvgis/general-information/usage-conditions-data-protection_en) и ограничения прав на кривую EWT / авторскую нагрузку указаны в протоколе. Копии паспортов в новый пакет не добавлялись. Единую открытую лицензию всему пакету не приписываем.

## Проверка и воспроизведение

`validation.json` сохраняет проверки календаря, полноты, диапазонов и сводки каждого года. `independent_validation.json` проверяет все 166536 строк другим, скалярным способом, соответствие подмножеств, 96 исключённых часов, SHA256 и весь 2023 год против прежнего CSV. Максимальное расхождение преобразований менее 3e-12; расхождение со старым CSV менее 1e-12. Пропусков, дубликатов, NaN/Inf нет. PV во всех 19 фиксированных зимних окнах нулевой. В полном наборе из 8760 часов годовая удельная PV-выработка составляет 763.18–924.71 кВт·ч/кВт, средний ветровой коэффициент 0.33170–0.38887; эти сводки не использовались для отбора лет.

Из корня репозитория:

```sh
python3 research_continuation_2026-10-13/online_pilot_2026-10-16/data/prepare_data.py
python3 research_continuation_2026-10-13/online_pilot_2026-10-16/data/verify_data.py
```

Новых зависимостей нет: стандартная библиотека и установленный NumPy 2.0.2. `fetch_weather.py` хранит лимит обращений и журнал; при наличии успешного ответа повторный запуск ничего не скачивает. В выполненной загрузке первая попытка получила DNS-ошибку песочницы; единственный повтор через разрешённый curl вне песочницы успешен. Бюджет новых запросов исчерпан, дополнительные погодные обращения для воспроизведения не нужны.
