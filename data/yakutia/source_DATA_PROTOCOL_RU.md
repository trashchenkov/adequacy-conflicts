# Протокол данных пилота управления без знания будущего

Зафиксирован 15.10.2026 до загрузки новых лет и преобразования данных; дата папки задана заданием. Основания: [задание](../../ONLINE_PILOT_TASK_RU_2026-10-15.md), [исследовательские правила](../../../RESEARCH_RULES.md). Область этой ветки — только подготовка данных; управление, выбор правил и оптимизация мощности не выполняются.

1. Состав лет фиксирован: все 19 лет 2005–2023, равный вес в последующем опыте. Точка 71.7775° N, 139.8471° E, PVGIS 5.3, PVGIS-ERA5. Погода — реанализ, не площадочные измерения. Годы не ранжировать по погоде, ENS, LOLH или результатам управления.
2. Бюджет: один запрос `seriescalc` за 2005–2022; 2023 берётся побайтно из сохранённого `mechanism_study_2026-10-15/winter_sources/raw/pvgis_era5_2023.json`. Допустим только один повтор того же запроса при технической ошибке. Сохранять запрос, код завершения, время, исходный JSON и SHA256. При исчерпании бюджета сообщить точный блокер; не подменять недостающие годы.
3. Параметры PV совпадают с зимним опытом: 1 кВт пикового номинала, c-Si, свободная установка, наклон 60°, азимут PVGIS 0° (юг), потери 14%, без слежения, расчётный горизонт рельефа. `pv_cf = P / 1000`, поскольку API возвращает P в ваттах для 1 кВт установленной мощности. Это доступная модельная генерация, не измеренная выработка объекта.
4. Ветер: EWT DW54-500; использовать сохранённую оцифрованную кривую и её SHA256, не оцифровывать повторно. Высота 40 м, `v40 = WS10m * (40 / 10) ** (1 / 7)`; линейная интерполяция кривой, ноль при v40 < 3 или v40 >= 25 м/с; `wind_cf = Pwind / 500`. Не вводить плотностные, температурные, эксплуатационные или ледовые поправки. Модель предполагает работоспособность ВЭУ; ограничения прежнего источника сохраняются.
5. Временная ось: исходные значения `YYYYMMDD:HH30` трактуются как середина часа UTC. Сохранить и середину, и начало часа `:00`. Не интерполировать время или значения. Для каждого полного года сохранить исходные 8760/8784 часа в отдельном NPZ. Високосные 2008, 2012, 2016, 2020 должны содержать 8784 часа; их оригинальные JSON и массивы не сокращать.
6. Для основного сравнения сформировать отдельный массив `(19, 8760)`: из високосных годов явно удалить только 24 часа 29 февраля, остальные реальные timestamps не перенумеровывать. Сохранить маску/индексы исходных часов и удалённые timestamps. Разрыв календарного времени на 25 часов после 28 февраля документируется как следствие исключения суток, а не пропуск источника; модельный шаг остаётся 1 час. Дополнительно сохранить для всех лет одно и то же календарное окно 20 ноября 00:00 — 31 декабря 23:00 UTC, ровно 1008 часов; форма `(19, 1008)`.
7. Обе нагрузки модельные, одинаковые по суточной форме для всех лет, без сезонности. Основная: `1000 * (1 + 0.05 * cos(2*pi*(h_local-18)/24)) / 1.05` кВт. Чувствительность: 24-часовая зимняя форма из прежнего `yukagir_typical_winter_model_24h.csv`, уже нормированная на пик 1000 кВт. `h_local = (h_UTC + 10) mod 24` — прежнее назначенное допущение, не исследование исторических часовых поясов. Не называть нагрузки измеренным потреблением Юкагира.
8. Масштаб ВИЭ фиксирован на подготовке данных: ветер 3000 кВт, PV 500 кВт. Для каждой нагрузки сохранить `x = 3000 * wind_cf + 500 * pv_cf - load` в кВт. Добавки на водородные собственные нужды здесь нет; согласование её режима относится к оборудованию и управлению лидера. Масштаб по полученным результатам здесь не изменять.
9. Пропуски, NaN/Inf, дубликаты или неверный часовой шаг в исходном году — ошибка готовности. Не заполнять их и не удалять год молча. В исходных флагах PVGIS `Int` сохранить реконструкцию API; наличие этого флага не равнозначно отсутствующему часу. Проверить координаты, параметры запроса, полный календарь каждого года, 24 удалённых часа в каждом високосном году и 1008 часов каждого зимнего окна.
10. Выход: исходный много-летний JSON и архив 2023; машиночитаемый манифест с URL/параметрами/SHA256; NPZ каждого исходного года; сводные NPZ 8760 и 1008; описание схемы и короткий отчёт о готовности. Сравнить весь год 2023 с прежним CSV независимым чтением. Пересчёт использовать только Python/NumPy стандартного установленного окружения, без новых зависимостей.
